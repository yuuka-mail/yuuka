# 品牌与吉祥物

> yuuka 设计文档的一部分。节号沿用整份设计的全局编号，索引见 [docs/design/README.md](README.md)。

## 14. 品牌与吉祥物

§11.1 让 yuuka 承担系统的声音，§12.8 把界面的色相全部留给表意。这一节定的是剩下的部分：
吉祥物和 logo 长什么样、出现在哪、以什么授权发布。它同时是给画师的约稿说明。

logo 和字标已经定稿，成品在 [`web/src/brand/`](../../web/src/brand/)。角色部分仍是设计草案，素材还没进仓库。

### 14.1 原则：一个记忆点

吉祥物靠**一个**一眼能认的特征加固定配色被记住，其余都可有可无。
元素越多，每张图要画对的东西就越多，缩成头像时能留下的也还是那一个。
所以这里只规定记忆点和固定项，服装、道具、姿势留给每张图自己决定。

放弃的是「每个细节都有寓意」的设定感。代价是角色不靠设定讲故事；
换来的是任何人照着这一节都能画出认得出的 yuuka，十年里换画师也不走样。

### 14.2 角色

- **气质**：平静、温和、可靠。她说的是系统确认过的事实（§11.1），语气平稳就够，不需要夸张或严厉
- **口气**（Telegram、空状态这类有文案的地方）：短句、数字在前、不用感叹号和 emoji。
  §12.5 的区分仍然靠颜色、标记和署名，口气只是配合
- **arisu** 是另一个角色，以后单独设计。两者的形状语言相反：yuuka 方、arisu 圆（§12.5）

### 14.3 记忆点：帽子

藏青帽身、青色帽檐，正面是信封小怪（§14.5）的徽章。**每一张图都有这顶帽子**，
头像、贴纸、Q 版都一样；只要帽子在，缩到 64px 也认得出是她。

### 14.4 固定项与可选项

固定，每张图都一样：

| 项 | 定法 |
|---|---|
| 发型 | 齐下巴的短发。戴帽后剪影由帽子决定，头发只露两侧，长发在小图里只会变成一团色块 |
| 发色 | 偏蓝的紫。色相要和 `--agent`（[`web/src/index.css`](../../web/src/index.css)）拉开：系统的角色顶着 agent 的颜色，两个 bot 头像并排时就分不清谁在说话，正是 §11.1 要避免的 |
| 眼色 | 和帽檐同一个青，少一个色相 |
| 配色 | 藏青、青、奶油白三色为主，加发色。青只取一个值，帽檐、徽章、logo、服装上的小块都用它 |

青是插画和 logo 的品牌色，**不回流到界面 token**：比 `--system` 鲜得多，挪进界面会和 `ring` 的蓝挨在一起。
logo 用的三色是藏青 `#213145`、青 `#69CEF4`、奶油白 `#FEF7F0`；发色定稿时再补。

可选，按画面需要决定：外套、斜挎包、笔和本子、服装上的青色方块。不画也不影响辨认。
小怪在同一张图里出现一次就够（帽子上那个）；包面上再画一个会和帽子抢焦点。

### 14.5 logo：信封小怪

横向的圆角矩形，顶边是信封折口的 V 形，右上角一块青色折角；奶油白的脸上两点眼睛、一道平嘴。
它是 logo、帽子徽章和应用图标的同一个东西。字标是小写 `yuuka`，Fredoka 600（SIL OFL）转曲成路径，
不依赖字体加载，Fredoka 也不扩散到界面正文。成品由美术制作流程导出，这里只放副本，不手改、不重画。

- **深底用反白版**：彩色版的藏青外框在暗底上看不见。`Logo` 用 `<picture>` 按系统偏好切换，和界面的颜色 token 同一个依据
- **组合整体缩放**：横排、竖排的比例是定稿的一部分。顶栏 44px 高放不下建议的 160px 宽，横排在那里约 124px 宽，
  实际看字标和小怪都读得清；SVG 内置留白由布局用负边距对齐到正文左缘
- **favicon 不带底**：完整的小怪居中放在方形画布上，不压成方的，暗色时在 SVG 内切换成反白版。
  比较过藏青圆角方底：外框并进底色，暗色 1x 屏的小尺寸上脸更突出，也留得住青色。选不带底，因为小尺寸下视觉重心更合理，favicon 也就是定稿的 logo；
  代价是暗色下小尺寸偏弱、没有青色，而且切换跟随系统或浏览器的配色，不一定等于标签栏的实际颜色
- **要求实底的场合**（PWA 图标、头像）把小怪放进圆角方形底里，而不是把它压成方的。方底也正好是系统标记的形状（§12.5）。
  这些场合的成品还没有做
- **16px 还没有专用版本**：现在的 favicon 只是同一张图缩放。2x 屏上折角和折口都读得出；1x 屏的 16px 上折角缩成一个色点、
  V 形折口糊掉。早先定的「32px 及以下去掉折角」没有验证过，不预先采用，等专用版本一起定

### 14.6 出现在哪

README 横幅、GitHub 社交预览、登录与 passkey 注册页、404、空收件箱，以及 yuuka 的 Telegram bot 头像。
**三栏工作界面里不放**——那是一天打开几十次、每次几秒的工具（§12.8），角色在那里只是噪音。
logo 只出现在顶栏左上角、登录页和 favicon（[`web/src/components/logo.tsx`](../../web/src/components/logo.tsx)）。

### 14.7 交付物

| 项 | 规格 | 用在 |
|---|---|---|
| logo | SVG：带字标横版、竖版、单独小怪，各一份单色版和反白版；随系统切换的 favicon；圆角方底图标（待做） | 顶栏、favicon、PWA、README |
| 角色立绘 | 全身一张、半身一张，透明底，长边 ≥ 2048px | README 横幅、登录页 |
| 头像 | 方形 512px，圆形裁切也成立，缩到 64px 认得出 | Telegram bot、GitHub org |
| 表情 | 平常、开心、为难三张，半身或头像大小 | 空状态、错误页、Telegram |

角色源文件要分层（PSD / Krita 任一），另出 PNG @1x @2x。logo 必须是手做的矢量，不接受位图描摹。

### 14.8 授权

吉祥物和 logo 的美术资源用 **CC BY 4.0**，和代码的许可证分开，放在单独的目录并附 `LICENSE`
（logo 和字标在 [`web/src/brand/`](../../web/src/brand/)），README 里写明作者署名。先例是 Go 的地鼠（Renee French，CC BY 3.0）。
约稿时合同要写明作者以 CC BY 4.0 授权、署名方式，以及委托方可修改与再分发。

进仓库的只能是有明确作者、能授权的源文件。草案和生成工具的产出只作参考：
没有作者的图在不少法域不受著作权保护，也就谈不上 CC BY 授权。
logo 的路径依据概念图用代码绘制，没有做自动描摹，字标由 OFL 字体转曲，都不是生成工具直接产出的图；由维护者以 CC BY 4.0 发布。

放弃的是「所有权利保留」带来的控制：任何人都能拿去改。换来的是 fork 和打包者不用来问，
十年里也不会因为一张图卡住发布。
